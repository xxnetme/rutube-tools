# Новые функции RuTube Tools — продуманный план

> **Статус на 29.10.2026:** A1–A7, B1, B4, B5 и часть B2 реализованы в версии **1.3.0**.
> Не сделано (осознанно): B3 «только звук M4A» (mux.js всегда собирает обе дорожки —
> нужен свой демультиплексор), C1 запись эфира, C2 докачка после перезапуска, C3 экспорт глав
> (главы есть в «Ещё», копирование текстом — есть; экспорт в CSV — нет).

Черновик развития после 1.1.0. Здесь: что предлагаю добавить, зачем это пользователю,
как технически сделать, сколько это стоит и в каком порядке выпускать.

---

## 1. Принципы отбора

Берём функцию, только если она проходит все четыре фильтра:

1. **Польза массовому пользователю** — не «фича ради фичи». Скачать, посмотреть, найти кадр, показать другу.
2. **Не ломает RuTube** — никаких подмен плеера, рекламы, обходов оплаты и DRM. Только надстройка над публичным API.
3. **Работает локально** — без серверов, аккаунтов и аналитики (это же обещано в политике приватности).
4. **Проходит ревью AMO/CWS** — без `eval`, удалённого кода и лишних разрешений.

Отдельно: каждая функция должна быть **отключаемой** в настройках, если она меняет поведение плеера.

## 2. Что уже подтверждено в API (факты, на которых строятся фичи)

Проверял на живом RuTube, не по документации (её нет):

| Данные | Где | Что это даёт |
|---|---|---|
| `captions[]` → `{code, langTitle, format: "srt", file: "https://pic.rtbcdn.ru/…srt", is_autogenerated}` | `api/play/options/<id>/` | **Субтитры отдаются готовым SRT** — скачивание в один запрос, без парсинга потока |
| `thumbnail_url` | `options` и `api/video/<id>/` | Превью в один клик |
| `cuepoints[]` | `options` | Главы/метки времени (у тестового видео пусто, формат известен) |
| `api/playlist/custom/<id>/videos/?limit=&offset=` → `results[]` | плейлисты | **Пакетная загрузка плейлиста целиком** |
| `videos_count`, `total_views`, `created_ts`, `author` | `api/video/<id>/` | Инфо-панель о видео |
| Мастер-плейлист содержит **дубли каждого качества** с разных CDN (`river-3-359.rtbcdn.ru`, `river-1.rutube.ru`) | `video_balancer.default` | **Failover между CDN** — сейчас мы лишние дубли просто выбрасываем |
| `duration` = **мс** в `options`, **сек** в `api/video/<id>/` | — | Не путать при расчётах |

Вывод: три самые желанные функции (субтитры, превью, плейлист) стоят дешевле, чем кажется —
данные уже лежат в том же ответе API, который мы запрашиваем для списка качеств.

## 3. Уровень A — релиз 1.2 «массовый» (≈2–3 дня)

Цель: чтобы случайный пользователь нашёл для себя причину оставить расширение.

### A1. Скачать фрагмент (обрезка по таймкодам) ⭐ самая ожидаемая
**Пользователь:** «нужен кусок с 12:30 до 12:45» — не качать 40-минутное видео целиком.
**Как:** в панели рядом с «Скачать MP4» — переключатель «Весь ролик / Фрагмент», два поля
«с» и «по» с подстановкой текущей позиции плеера кнопкой «взять из плеера».
**Техника:** `planParts()` уже умеет работать с подмножеством сегментов — передаём
`segments.slice(fromSeg, toSeg)`. Точность — до сегмента (2–4 с), границы подсвечиваем в UI
(«от 12:28, до 12:46»), чтобы не было сюрпризов.
**Оценка:** S (4–6 ч). **Риск:** низкий.

### A2. Субтитры и превью
**Пользователь:** скачать .srt (в т.ч. авто-субтитры RuTube) и обложку видео.
**Как:** в панели — блок «Ещё»: список дорожек субтитров (`langTitle` + пометка «авто») →
скачивание `.srt`; кнопка «Обложка» → `thumbnail_url` как `.jpg`.
**Техника:** те же данные, что уже приходят; конвертация SRT→VTT — 20 строк на будущее (для плееров).
**Оценка:** S (3 ч). **Риск:** низкий.

### A3. PiP / мини-плеер
**Пользователь:** смотреть, пока листаешь другие вкладки RuTube.
**Как:** кнопка в панели (и клавиша <kbd>p</kbd>) → `video.requestPictureInPicture()`;
если браузер поддерживает Document PiP — «открепить» с нашими кнопками покадровой перемотки.
**Оценка:** S (3 ч). **Риск:** низкий (нужна проверка, что RuTube не ломает PiP своим оверлеем).

### A4. Failover между CDN + «умный» повтор
**Пользователь:** загрузка не срывается, если один сервер RuTube тупит.
**Как:** не схлопывать дубли вариантов, а хранить как список зеркал; при 3 подряд ошибках
сегмента — переключиться на следующее зеркало и продолжить с того же номера.
**Техника:** `dedupeVariants()` → `groupVariants()` c `mirrors[]`; в `downloadPart` — счётчик
ошибок на сегмент и смена базового URL. **Плюс:** общий счётчик «скачано с зеркала №2» в диагностике.
**Оценка:** M (6–8 ч). **Риск:** низкий, но требует аккуратных тестов.

### A5. «Сообщить о проблеме» (диагностика)
**Пользователь:** что-то не скачалось — одной кнопкой копирует готовый текст для письма/issue.
**Как:** в панели при ошибке — «Скопировать диагностику»: версия, браузер, id видео, качество,
кодек, на каком сегменте упало, текст ошибки, использованный CDN. Без персональных данных.
**Оценка:** S (2–3 ч). **Риск:** нулевой. **Эффект:** резко снижает стоимость поддержки в массах.

### A6. Инфо о видео
**Пользователь:** «какой битрейт/кодек/когда выложено, сколько весит в 1080p».
**Как:** раскрывающийся блок: кодек, fps, разрешения и оценки размера, дата, просмотры, автор,
кнопка «Скопировать как текст».
**Оценка:** S (3 ч). **Риск:** низкий.

### A7. Доступность и локализация
**Пользователь:** те, кто ходит с клавиатуры/скринридера, и англоязычные.
**Как:** `aria-label` на кнопках, видимый фокус, поддержка `prefers-reduced-motion`,
контраст ≥ 4.5:1; строки → `_locales/{ru,en}/messages.json` через `browser.i18n`.
**Оценка:** M (1 день). **Риск:** нулевой, **но:** это пункт, который любят проверять ревьюеры.

## 4. Уровень B — релиз 1.3 «для активных» (≈5–7 дней)

### B1. Пакетная загрузка плейлиста ⭐
**Пользователь:** сериал/курс из 30 серий — поставить в очередь и уйти пить чай.
**Как:** на странице `/plst/<id>` появляется кнопка «Скачать плейлист»: выбор качества,
диапазон серий, лимит одновременных (1–2), очередь с паузой/отменой, статусы по каждому видео.
**Техника:** `api/playlist/custom/<id>/videos/?limit=50&offset=…` → очередь задач в background
(уже есть каркас `jobs`), последовательный запуск, состояние очереди в `storage.local`
(переживает перезапуск браузера), пауза = не брать следующую задачу.
**Оценка:** L (2–3 дня). **Риск:** средний — упрёмся в лимиты CDN при параллельности, поэтому 1–2 потока и пауза между задачами.

### B2. Раскадровка / серия кадров в ZIP
**Пользователь:** «каждый 10-й кадр» или «кадр каждые 5 секунд» — для превью, раскадровок, конспектов.
**Как:** в панели «Кадры»: интервал (сек или кадры), лимит, качество → ZIP с `frame-0001.png…`
и `index.csv` (номер, таймкод).
**Техника:** canvas → `toBlob` → ZIP. Нужен мини-ZIP (store-only, без сжатия) ~120 строк,
либо `CompressionStream('deflate-raw')` — есть в Firefox 113+/Chromium 80+, сжатие бесплатно.
**Оценка:** M (1–1.5 дня). **Риск:** средний на длинных видео (память) — решаем лимитом и потоковой записью.

### B3. Только звук (M4A)
**Пользователь:** подкаст/лекция — слушать в дороге, файл в 10 раз меньше.
**Как:** переключатель «Видео / Только звук» в панели качеств.
**Техника:** поток — muxed MPEG-TS; нужно вытащить AAC из PES и собрать M4A (sample table).
`mux.js` умеет transmux в MP4, но аудио-онли режима «из коробки» нет → вариант:
Transmuxer → получившийся fMP4 → вырезать аудио-трек своим мини-муксером, либо писать
свой TS-демультиплексор (≈300 строк).
**Оценка:** L (2 дня). **Риск:** средний-высокий (нужны побитовые тесты и проверка ffprobe на 3–5 видео).

### B4. Точная навигация для «кадровых» задач
* «Перейти на кадр №» (поле ввода), шаг 1/2 кадра (<kbd>Shift</kbd>+<kbd>,</kbd> / <kbd>.</kbd>);
* A/B-петля: отметить начало/конец (<kbd>i</kbd>/<kbd>o</kbd>), повторять фрагмент;
* лупа кадра (2×/4× по <kbd>z</kbd>) — увеличить область вокруг курсора.
**Оценка:** M (1 день). **Риск:** низкий. **Кому:** монтажёрам, преподавателям, разбору техники.

### B5. Переназначение клавиш
**Как:** `commands` API для глобальных + своя таблица в настройках для страничных;
конфликты показываем сразу. Экспорт/импорт настроек в JSON.
**Оценка:** M (1 день). **Риск:** низкий.

## 5. Уровень C — релиз 2.0 «дерзкое»

### C1. Запись прямого эфира
**Пользователь:** «запиши стрим, я не успеваю».
**Как:** кнопка «Записать эфир» с таймером (до конца / N минут), остановка вручную.
**Техника:** live-плейлист без `#EXT-X-ENDLIST` → опрос каждые 2–4 с, добавление новых сегментов,
`EXT-X-DISCONTINUITY` → новая часть файла. Ограничения: DVR-окно, реклама в эфире, размер.
**Оценка:** L (2–3 дня). **Риск:** высокий (нестабильные плейлисты, «бесконечная» запись, права).
**Решение:** только по явному нажатию, с таймером и предупреждением — не автозапись.

### C2. Возобновление прерванной загрузки
**Как:** сегменты складываются в IndexedDB по мере скачивания, при перезапуске браузера —
«Продолжить загрузку» вместо «начать заново».
**Оценка:** L (2–3 дня). **Риск:** средний (квоты IndexedDB, чистка мусора, миграции схемы).

### C3. Экспорт глав и таймкодов
`cuepoints` + закладки пользователя → `.csv`/`.txt` со ссылками вида «видео + таймкод».
**Оценка:** S (4 ч). **Риск:** низкий. **Зависимость:** проверить формат `cuepoints` на 5–10 видео.

### C4. Плеерные мелочи
Скорость с коррекцией тона (`preservesPitch`), усиление громкости до 300 %
(Web Audio), «запомнить позицию» и «продолжить с места» для длинных лекций.
**Оценка:** M (1 день). **Риск:** низкий.

## 7. Предлагаемый план выпусков

**1.2 «Массовый» (сейчас).** A1 + A2 + A5 + A3 + A6 + A7.
Итог: расширение перестаёт быть «только для качающих» — им можно пользоваться каждый день.
Это же лучший аргумент для карточки в AMO («скачать фрагмент», «субтитры», «кадр в PNG»).

**1.3 «Для активных».** B1 + A4 + B4 + B5.
Итог: плейлисты и надёжность; расширение начинают советовать в комментариях.

**2.0 «Дерзкое».** B2 + B3 + C2 (+ C1 по результатам опроса пользователей).

**Правило:** каждый релиз — новое «заголовочное» умение + одна надёжностная правка.
Так в changelog всегда есть что показать, а отзывы не копятся в «не работает».

## 8. Чего сознательно не делаем

| Идея | Почему нет |
|---|---|
| Обход DRM / скачивание платного контента | вне закона, вылет с AMO, блокировка |
| Подмена/отключение рекламы RuTube | ломает монетизацию сервиса, конфликт с площадкой |
| Эмуляция подписки / «Premium-функции» | прямое нарушение |
| Серверная часть, аккаунты, аналитика | противоречит обещаниям приватности и усложняет поддержку |
| Автоматический постинг обратно на RuTube | не наша задача, лишние разрешения |
| Встраивание своего плеера вместо RuTube | ломается при каждом релизе площадки |

## 9. Критерии готовности любой новой функции

1. Работает в Firefox ESR и в Chromium-сборке.
2. Отключается в настройках, если вмешивается в плеер.
3. Не добавляет новых разрешений (или объяснено в PRIVACY и PUBLISH).
4. Есть тест-сценарий, который я прогоняю руками на реальном видео (как в README).
5. В `CHANGELOG.md` — одна строка, понятная не-технарю.
6. Если функция про скачивание — файл проверен `ffprobe` на валидность.

## 10. Как измерять успех без телеметрии

Раз аналитики нет, смотрим на внешние сигналы:
* отзывы в AMO: доля упоминаний «не работает» / «не скачивается»;
* количество issue с метками `download` / `player` / `feature`;
* возвраты к «Повторить загрузку» (локальный счётчик в `storage.local`, только по кнопке, никуда не уходит);
* доля пользователей, включивших полный набор клавиш (локально) → подсказывает дефолт для новых версий.
