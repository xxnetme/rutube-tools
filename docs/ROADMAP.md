# План развития RuTube Tools

> Публичный `main` сверен 06.11.2026 на коммите `d9810a3` (версия в исходниках — 1.8.0).
> Технические статусы 1.9 и предварительного OPFS-прототипа ниже обновлены по локальной ветке
> после этого коммита: они ещё не означают push или Release. `docs/FEATURES.md` сохранён как история идей.
>
> Статусы: **готово в main** — код и автотесты есть в репозитории;
> **опубликовано** — это отдельно подтверждённый Release/магазин;
> **частично** — выполнена только указанная часть; **внешний шаг** — нужен аккаунт владельца.

## 1. Текущая точка

- **Исходники:** удалённый `main` содержит 1.8.0; Checks на `d9810a3` успешен. В локальной
  ветке после него реализованы технические пункты 1.9: 104/104 JS и 15/15 Python-тестов, ESLint,
  `tsc --checkJs`, воспроизводимая сборка, версии, изображения и SHA-256 зелёные;
  `addons-linter`: 0 ошибок и 1 предупреждение о минимальной версии Firefox для Android.
  Browser E2E в Firefox и Chromium прошёл с настоящим MP4 и `ffprobe`.
- **GitHub Release:** последний публичный релиз — `v1.7.0`; тег и Release `v1.8.0`
  на момент сверки ещё не созданы. <!-- ver:prev -->
- **AMO:** публична 1.7.0; версия 1.8.0 ещё не подана. В карточке 9 скриншотов,
  у preview №3 не заполнена подпись. <!-- ver:prev -->
- **OPFS-прототип:** Worker + OPFS локально работает в обоих браузерах на 64 МиБ; размер и CRC32
  проверены, очистка возвращает usage к baseline. Есть предварительный сигнал меньшего пика RSS,
  но скорость в Firefox хуже. Файл около 2 ГиБ, экспорт в `downloads` и производственная интеграция
  не проверялись; текущий путь загрузки не менялся. Подробности — `docs/OPFS-PROTOTYPE.md`.
- **Сайт:** уже обновлён до 1.8.0 и совпадает с `docs/` из `main`.
- **Chromium:** пакет, тексты и изображения для Chrome/Edge/Opera подготовлены,
  но подача не подтверждена. Нужны аккаунты владельца; для Chrome также 2FA и регистрационный взнос.

Следовательно, «1.8 готово» означает **готово в коде**, но не «пользователи уже получили 1.8».
Первый отдельный шаг — опубликовать 1.8.0 либо явно принять решение пропустить этот релиз.

## 2. Полная сверка предложенного плана

### 1.8 «Кадры»

| Пункт | Статус | Что подтверждено / чего не хватает |
|---|---|---|
| Предупреждение «получится `.ts`» до старта для HEVC/AV1 | **Готово в main** | Несовместимое качество помечено `.ts`; после выбора показано пояснение до запуска. Есть jsdom-тест |
| Копирование кадра в буфер | **Готово в main** | Кнопка и клавиша `c`; в буфер отправляется PNG, при недоступном API показывается ошибка. Браузерный E2E 1.9 проверяет загрузку MP4; отдельный сценарий именно для clipboard не добавлялся |
| JPEG/WebP с настройкой качества | **Готово в main** | PNG остаётся по умолчанию; формат и качество действуют на одиночные кадры, серию и контактный лист. Расширение файла меняется автоматически |
| Контактный лист с таймкодами | **Готово в main** | Общий расчёт моментов с серией, уменьшение кадров при съёмке, ограничение canvas 8192 px; есть тесты раскладки |
| Серия между A и B по шагу или каждый кадр | **Частично** | Серия **по временному шагу** внутри A–B есть, включая A/B в обратном порядке. Режима «каждый кадр» нет: минимальный шаг сейчас 0,2 с, до 120 кадров |
| Запоминание скорости для каждого видео | **Не сделано** | Переключение скорости и сохранение тона есть, позиция просмотра запоминается, но `playbackRate` не сохраняется по `videoId` |

### 1.9 «Доверие и распространение»

| Пункт | Статус | Что подтверждено / чего не хватает |
|---|---|---|
| Edge, Chrome Web Store, Opera | **Внешний шаг** | Пакеты и материалы карточек подготовлены. Подачи и публичные страницы не подтверждены; аккаунты/2FA/оплата выполняются владельцем |
| Явный `content_security_policy` | **Готово локально** | Оба манифеста явно фиксируют restrictive CSP extension pages; `unsafe-eval` и удалённого кода нет. Есть Python-проверка манифестов |
| DOM-конструктор вместо `innerHTML` + `no-unsanitized` | **Готово локально** | Динамические панели переведены на безопасный DOM-конструктор; линтер запрещает опасные присваивания, XSS-строки API в тестах остаются текстом |
| Тест «сети нет, кроме RuTube» | **Готово локально** | `RTNetwork` проверяет все входящие URL и каждый редирект; Node-тесты включают чужой `Location` и `opaqueredirect`. В браузерном E2E CONNECT-прокси записывает все попытки и падает на любом хосте вне стенда |
| JSDoc + `tsc --checkJs`, начиная с `engine.js` | **Готово локально** | Добавлены типы API/HLS/задач, `jsconfig.json` и отдельный шаг typecheck в CI; шум jsdom после teardown устранён |
| Минимальный E2E в Firefox и Chromium | **Готово локально** | Настоящие MV3/XPI загружаются в браузеры, локальный HLS скачивается через UI. Оба результата — MP4, H.264 + AAC, 27 323 байта, около 2,005 с по `ffprobe`; отдельный CI-job прикладывает отчёты и сетевые журналы |

### 1.10 «Менеджер загрузок»

| Пункт | Статус | Что подтверждено / чего не хватает |
|---|---|---|
| Единая вкладка: очередь, скорость, пауза, повтор, ошибки | **Частично** | У активной загрузки показаны прогресс и скорость; плейлист последовательно ставится в очередь, у него есть пауза/отмена. Есть повтор, докачка и история 30 файлов. Нет единого менеджера, паузы одиночного видео и списка ошибок/повтора по каждой серии |
| Проверка файла и его длительности после сборки | **Не сделано в продукте** | `ffprobe` используется в тестах M4A, но обычная загрузка не сверяет полученную длительность с ожидаемой и не помечает подозрительный результат |
| Настройки потоков, таймаутов и лимита скорости | **Не сделано** | Параллельность и таймаут заданы константами в коде. Пользовательских безопасных пределов и ограничения скорости нет |
| Экспорт/импорт настроек файлом | **Готово локально** | JSON со `schemaVersion: 1`, allowlist и строгой проверкой значений. История/очередь не переносятся; ошибка записи откатывает прежние значения. Chromium E2E проверяет валидный/невалидный импорт и откат в настоящем popup |
| Ближайшее качество, если выбранное недоступно | **Готово при выборе** | `pickVariant()` выбирает ближайший по высоте вариант, а `best`/`worst` обрабатывает отдельно. Автоматического понижения качества в середине уже идущей загрузки нет — это отдельная задача, не часть выполненного пункта |

### 1.11 «Точность»

| Пункт | Статус | Что подтверждено / чего не хватает |
|---|---|---|
| Два маркера на шкале с превью-кадрами | **Не сделано** | A/B-петля и ввод таймкодов есть; визуальных маркеров на шкале RuTube и превью у них нет |
| Прототип `requestVideoFrameCallback` | **Не сделано** | API в исходниках не используется. Текущий шаг по кадрам основан на FPS и `currentTime` |
| SRT → VTT | **Не сделано** | Готовый SRT скачивается; конвертера VTT нет. ASS остаётся отдельной задачей и в этот пункт не входит |
| Доступность: фокус, `aria-live`, reduced motion | **Частично** | Есть `aria-label`, `role`, `:focus-visible` и `prefers-reduced-motion`. Нет полноценного focus trap/возврата фокуса, живых объявлений прогресса и автоматических a11y-проверок |
| Украинский и белорусский | **Не сделано** | Словари только RU/EN. Автоопределение `uk`/`be` сейчас выбирает русский — это fallback, а не перевод |

### 1.12 «Память»

| Пункт | Статус | Что подтверждено / чего не хватает |
|---|---|---|
| Запись потока в OPFS из Worker | **Изолированный прототип локально** | `tests/opfs/` пишет через `createSyncAccessHandle()` в Firefox и Chromium, проверяет размер/CRC32 и удаляет файл. В производственном загрузчике OPFS по-прежнему нет |
| Замеры памяти и скорости на файле около 2 ГБ | **Частично: только 64 МиБ** | Есть воспроизводимый стенд и один предварительный прогон на 64 МиБ. Пик ΔRSS ниже с OPFS в обоих браузерах, но полный цикл в Firefox медленнее. Замер 2 ГиБ не выполнялся; квота текущего Firefox-профиля около 99 МиБ |
| Докачка внутри части по индексу сегментов | **Не сделано** | Докачка с границы сохранённой части или серии уже работает; незавершённая часть начинается заново |
| Квота, очистка и восстановление индекса OPFS | **Частично в прототипе** | Записаны quota/usage, отсутствие файла после очистки и возврат usage к baseline. Индекса сегментов и восстановления после перезапуска пока нет |

### 2.0.0 «Новое ядро»

| Критерий | Статус сейчас |
|---|---|
| OPFS по умолчанию + старый путь как fallback | **Не начато**; зависит от измерений 1.12 |
| HEVC/AV1 в fMP4 (`hvcC`/`av1C`) | **Не начато**; сейчас честный `.ts`-fallback, AVC/AAC → MP4 через bundled mux.js |
| Модульный исходный код с типами и автономной сборкой | **Не начато**; сейчас большие IIFE без шага модульной сборки |
| Миграция настроек 1.x | **Частично**: есть подстановка defaults, но нет версии схемы и явных миграций |
| Минимальные версии браузеров | Сейчас Firefox 140 и Chromium 109; повышение должно быть обосновано фактически используемыми API и записано в CHANGELOG |
| Хотя бы один магазин для Chromium | **Внешний шаг**, публикация не подтверждена |
| E2E в обоих браузерах как условие релиза | **Готово локально для текущего контура**: отдельный обязательный CI-job для Firefox/Chromium; будет применяться и к следующим релизам |
| Задокументированная и замороженная схема `rt:*` | **Не начато**; сообщения описаны только по коду и тестам |

Для миграции настроек сейчас есть лишь подстановка значений по умолчанию через
`storage.local.get(DEFAULTS)`. Нет версии схемы, явных миграций и теста на старые ключи —
поэтому этот критерий нельзя считать выполненным.

## 3. Доработанный состав релизов

### Сначала — публикация 1.8.0

Новый код не нужен. Проверить пакеты из `main`, создать `v1.8.0` и GitHub Release,
подать Firefox zip в AMO, после модерации сверить публичную версию. Заодно заполнить
подпись preview №3. Обновить этот документ и `PUBLISH.md`: убрать различие
«main 1.8 / публичный 1.7» только после фактической публикации. <!-- ver:prev -->

### 1.9 — доверие и воспроизводимая проверка

**Кодовый объём:**

1. Явно зафиксировать CSP extension pages в Firefox и Chromium без ослабления MV3.
2. Добавить маленький DOM-конструктор и перевести динамические панели на него.
   Включить `no-unsanitized`; вредоносные строки API должны остаться текстом в тестах.
3. Расширить сетевые проверки на все входящие URL и редиректы. В E2E фиксировать каждый
   внешний запрос и падать на любом хосте вне allowlist RuTube/CDN и локального стенда.
4. Ввести JSDoc-типы API/HLS/задач, начиная с `engine.js`; добавить `tsc --checkJs` в CI.
5. Поднять расширение в настоящих Firefox и Chromium на локальной имитации RuTube,
   выполнить сценарий и получить непустой файл. Проверить контейнер `ffprobe`.
6. Устранить шум jsdom после teardown: сейчас тесты проходят, но MutationObserver может
   выводить `TypeError` в лог после завершения отдельных сценариев.

**Параллельный внешний шаг:** владелец подаёт Chromium zip в Edge/Chrome/Opera.
Ревью магазина не подменяет технические критерии 1.9 и не должно бессрочно блокировать код.

**Готово, когда:** динамический `innerHTML` устранён либо безопасно изолирован и явно
обоснован, линтер и браузерные E2E проходят в CI, чужих сетевых запросов нет, типы проверяются.
Локально эти условия воспроизведены; прохождение именно GitHub Actions будет подтверждено после push.

### 1.10 — единый менеджер загрузок

1. Объединить активные задания, очередь плейлиста, незавершённые и историю в понятном окне.
2. Показывать состояние и ошибку каждой серии, повторять отдельную неудачную серию,
   поддерживать паузу/продолжение не только плейлиста, но и одиночной загрузки.
3. Проверять результат **до сохранения**: ненулевой размер, число сегментов, длительность
   и совместимость дорожек. Расхождение показывать пользователю, не выдавая его за успех.
   Чтение произвольного уже сохранённого файла с диска не обещать без отдельного пользовательского действия.
4. Добавить экспорт/импорт JSON с версией схемы, allowlist ключей, проверкой типов и откатом
   при ошибке; содержимое файла не должно становиться HTML.
5. Зафиксировать тестом уже существующий выбор ближайшего качества. Потоки, таймауты и лимит
   скорости выносить в настройки только после реальных отчётов и с безопасными границами.

### 1.11 — точность, управление и доступность

1. Два доступных маркера A/B на шкале с превью; синхронизация с клавиатурой, полями времени
   и честными границами HLS-сегментов.
2. Прототип `requestVideoFrameCallback`: сравнить с текущим шагом, отдельно проверить VFR.
   Только после этого решать, возможен ли режим серии «каждый кадр» и как честно нумеровать кадры.
3. Запоминание `playbackRate` по `videoId` с отдельной настройкой, ограничением числа записей
   и восстановлением только на том же видео.
4. Конвертер SRT → VTT с корректными таймкодами, текстом и тестами; ASS не маскировать под VTT.
5. Focus trap и возврат фокуса, `aria-live` для прогресса, клавиатурные вкладки, контраст
   и reduced motion; добавить автоматические проверки там, где они надёжны.
6. Полные украинский и белорусский словари с тестом отсутствующих ключей; RU остаётся fallback.

### 1.12 — память и докачка (после раннего прототипа)

Работа идёт за флагом, старый путь сохраняется:

1. Worker + OPFS в Firefox и Chromium.
2. Воспроизводимый файл около 2 ГБ; записать память, скорость, квоту и поведение при нехватке места.
3. Индекс сегментов внутри незавершённой части и восстановление после перезапуска.
4. Очистка временных файлов, защита от повреждённого индекса, понятные ошибки пользователю.
5. Выдача результата через `downloads` без повторной сборки всего файла в RAM там,
   где браузер действительно позволяет это подтвердить замером.

**Решение после замеров:** OPFS становится основным путём только при подтверждённом выигрыше
и приемлемой совместимости. Иначе остаётся разбиение на части, а критерии 2.0 пересматриваются явно.

### 2.0.0 — новое ядро

Мажорная версия выпускается не по числу функций, а когда выполнены технические условия:

- OPFS по умолчанию **если прототип 1.12 подтвердил применимость**, старый путь проверен как fallback;
- HEVC и AV1 упаковываются в fMP4 через корректные `hvcC`/`av1C`; `.ts` — только крайний fallback;
- модульные исходники и типы собираются в автономные пакеты без remotely hosted code;
  сторонние bundled-библиотеки и их лицензии не скрываются и не теряются;
- настройки 1.x проходят версионированную миграцию с тестами на старые ключи `storage.local`;
- протокол `rt:*` описан, версионирован и покрыт тестами совместимости;
- минимальные версии браузеров обоснованы API и указаны в CHANGELOG;
- E2E Firefox/Chromium обязателен для релиза;
- хотя бы один Chromium-каталог опубликован **либо** владелец явно зафиксировал решение
  по результатам ревью, чтобы внешний отказ не блокировал технический релиз бессрочно.

## 4. Технические границы, которые нельзя обещать заранее

### OPFS и размер файла

OPFS — переделка пути записи, а не замена `Blob` на `File` одной строкой. До замеров нельзя
обещать исчезновение потолка размера, одинаковое поведение Firefox/Chromium или сегментную докачку.

### HEVC/AV1

Текущий mux.js рассчитан на AVC/AAC. Изменение расширения `.ts` на `.mp4` проблему не решает.
Нужны demux/mux, `hvcC`/`av1C`, проверка `ffprobe` и воспроизведение в целевых плеерах.

### Кадры и VFR

`requestVideoFrameCallback` сообщает метаданные показанного кадра, но не даёт универсальный
абсолютный номер кодированного кадра после произвольного seek. Для VFR нельзя выдавать
`currentTime * fps` за гарантированный индекс.

### Точность вырезания

Пока используется копирование HLS-сегментов без перекодирования, границы фрагмента остаются
сегментными. Маркеры и превью улучшают интерфейс, но не делают разрез автоматически кадровым.

## 5. Сознательно не берём

- Запись эфиров и обход DRM, оплаты или ограничений доступа.
- Массовое скачивание каналов и страниц поиска целиком.
- Обещание «потолка размера больше нет» до воспроизводимых замеров.
- GIF/WebM из A/B как ближайшую функцию: `MediaRecorder`/WebCodecs требуют отдельной проверки
  границ, декодирования и памяти.
- Firefox для Android без отдельного исследования фонового режима, `downloads` и сенсорного UI.
- Усиление звука выше 100 % до отдельной проверки Web Audio, CORS, клиппинга и конфликта с плеером.
