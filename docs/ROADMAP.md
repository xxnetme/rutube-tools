## 1. Постоянная установка в Firefox — уже работает

В плане было: «дополнение слетает после перезапуска, подписать `.xpi` через unlisted».

Проверка: карточка [rutube-tools в AMO](https://addons.mozilla.org/ru/firefox/addon/rutube-tools/)
в статусе **public** с 01.11.2026, версия 1.3.2. Всё, что установлено из магазина,
живёт после перезапуска и обновляется само. Подпись `unlisted` для этого не нужна —
она нужна только для сборок, которые распространяются не через магазин.

Слетает только `.xpi` из GitHub Releases: это временное дополнение, так Firefox
обращается с неподписанными файлами. Так и должно быть.

Что действительно осталось: **в магазине лежит 1.3.2, а в `main` — 1.5.0**.
Пока новая версия не загружена, человек из магазина не увидит ни звука M4A,
ни докачки, ни субтитров одной галочкой, ни шаблона имени. Обновление — одна команда, см. `docs/PUBLISH.md` §7.

| | |
|---|---|
| Статус | **готово** для 1.3.2, для 1.5.0 — **нужны вы** (ключи AMO) |
| Что делать | `AMO_JWT_ISSUER=... AMO_JWT_SECRET=... python3 tools/amo-publish.py` |
| Время | 5 минут, проходит валидацию и ревью само |

Набор из девяти кадров 1280×800 переснят дважды: сначала на 1.4.0, затем на 1.5.0,

Съёмка идёт в два прохода: панель на локальной имитации RuTube с настоящими данными API

на живой загрузке с CDN, поэтому цифры на кадрах настоящие. Локальная только страница:
rutube.ru отдаёт её лишь из России.

| Статус | **готово** |

## 4. Мелкие функции — **готово, вошло в 1.5.0**

| Функция | Как сделано |
|---|---|
| Субтитры одной галочкой | В «Скачать» переключатель; `.srt` сохраняется рядом с видео и с тем же именем до расширения (`… — 1/2.srt` при нарезке), поэтому плеер подхватывает сам. При нескольких дорожках — выбор языка, выбор запоминается |
| Шаблон имени файла | `{title}`, `{author}`, `{quality}`, `{date}`, `{playlist}`; `/` создаёт подпапку. Пустая переменная не оставляет висящих разделителей. Работает для плейлиста и при докачке |
| Формат по умолчанию | Настройка «видео / только звук»: панель открывается на выбранном формате |

Проверено тестами: подстановка переменных и пути, имя `.srt` рядом с видео и с частью,
шаблон в плейлисте, формат по умолчанию в панели.

## 6. Релиз 1.7: движок (OPFS)

Запись на диск по ходу загрузки вместо накопления в памяти. Это уберёт нарезку
по 220 МБ и даст настоящую докачку с середины файла.

Риск описан в плане верно. Добавлю: в Firefox OPFS нет в фоновой странице MV3
так, как в Chromium, и запись из сервис-воркера требует `FileSystemSyncAccessHandle`
внутри Worker. Поэтому порядок такой: прототип на 200 строк, замер на файле
в 2 ГБ в обоих браузерах, и только потом переделка движка.

| Оценка прототипа | 1 день |
| Полная переделка | 3–5 дней, с риском, что в Firefox придётся оставить старый путь |

## 7. Инфраструктура

| Пункт | Статус |
|---|---|
| Автоматический релиз по тегу с текстом из CHANGELOG | **готово** — `.github/workflows/release.yml`, проверено на v1.4.0 |
| Dependabot для GitHub Actions | **могу сам**, 10 минут |
| E2E в настоящем Chrome и Firefox | **могу сам, но долго**: нужен Playwright с двумя браузерами и имитация RuTube. 1–2 дня |

Важно про E2E: они поймают то, чего не видит jsdom, — засыпание сервис-воркера,
`offscreen` в Chromium, реальную запись файла. Но поддерживать их дорого:
каждое изменение в вёрстке RuTube будет их ломать, а вёрстка меняется без
предупреждения. Предлагаю начать с одного сценария — «скачать 10 секунд
фрагмента и получить файл ненулевого размера» в обоих браузерах, — а не
с покрытия всего.

## 8. Чего не делаем — согласен с планом

* **Запись эфиров.** Юридический риск и почти гарантированный отказ на ревью.
* **Скачивание целых каналов.** Превращает инструмент в средство массового копирования.
* **Android.** Сначала проверить, есть ли в Firefox для Android `downloads` и замена
  `offscreen`; панель под сенсор переделывать точно придётся.
