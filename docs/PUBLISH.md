## 2. Firefox — addons.mozilla.org

Первый канал: бесплатный, даёт постоянную подпись, а Firefox — целевой браузер.

### Вариант через API (без браузера)

Если не хочется щёлкать формы, AMO умеет принимать загрузку через официальный API.
Куки и пароль для этого не нужны — только ключи JWT.

1. <https://addons.mozilla.org/en-US/developers/addon/api/key/> → **Generate new key**.
   Получите две строки: **JWT issuer** (`user:…`) и **JWT secret**.
2. Запустите:

```bash
AMO_JWT_ISSUER='user:...' AMO_JWT_SECRET='...' \
  python3 tools/amo-publish.py release/rutube-tools-firefox.zip
```

Скрипт загружает файл, ждёт валидацию, создаёт карточку с текстами из этого репозитория
(название, описание, категория «Photos, Music & Videos», лицензия MIT, заметка ревьюеру)
и отправляет версию на проверку. Повторный запуск добавляет новую версию к уже созданной
карточке, а не создаёт вторую.

Отзыв ключей — там же, кнопкой **Revoke**, в любой момент.

`/addons/addon/<slug>/eula_policy/`. Пока оно пустое, карточка выглядит недозаполненной.
Заполняется так (или руками в кабинете: <https://addons.mozilla.org/ru/developers/addon/rutube-tools/> → «Edit»):

```python
# короткий текст + ссылка на полную версию
privacy_policy = {"ru": "...", "en-US": "..."}
PATCH /api/v5/addons/addon/rutube-tools/eula_policy/
```

### Лимиты AMO, на которые легко налететь

| Действие | Лимит | Симптом |
|---|---|---|
| PATCH карточки (`/addons/addon/<slug>/`) | ~10 запросов в час | `429 Request was throttled` |
| Изменение EULA/приватности и загрузка скриншотов | отдельный суточный лимит | `429 … Expected available in 2700+ seconds` |

Отсюда правило: сначала собирайте всё в один PATCH, а не по одному полю. Если поймали 429 —
не повторяйте в цикле, это только продлевает блокировку; подождите указанное время.

### Автоматическое доведение карточки до готового вида

Правки, которые остались (политика, `en-US`, сайт поддержки, скриншоты 4–9), применяет
[`tools/amo-apply-all.py`](../tools/amo-apply-all.py). Он идемпотентный: читает состояние,
пропускает готовое, ждёт лимит по времени, которое сообщает сам AMO.

Два способа запустить:

**1. На GitHub, без вашего участия** — воркфлоу `.github/workflows/amo-card.yml` раз в час:

1. Settings → Secrets and variables → Actions → **New repository secret**
2. `AMO_JWT_ISSUER` = `user:...`, `AMO_JWT_SECRET` = 64 символа
3. Actions → «AMO — довести карточку до готового вида» → **Run workflow**

Дальше он сам будет пытаться каждый час и остановится, когда всё применится.
Секреты в репозиторий не попадают — GitHub подставляет их только в момент запуска.

**2. Локально, если хотите подождать в одной сессии:**

```bash
AMO_JWT_ISSUER='user:...' AMO_JWT_SECRET='...' python3 tools/amo-apply-all.py
```

### Честно о риске

Правила Chrome Web Store прямо запрещают «содействовать скачиванию контента в нарушение прав
правообладателей» и отдельно упоминают YouTube. Расширение для RuTube под эту формулировку
формально не попадает (это не YouTube), но ревьюер может счесть любой видеограббер
нарушением. Вероятность отказа реальная, и повлиять на неё из кода нельзя.

Что снижает риск:
* в описании — только свои формулировки про «сохранить видео, на которое у вас есть право»,
  без слов «скачать любое видео», «без ограничений», «обойти»;
* DRM и прямые эфиры явно не поддерживаются, и это написано в карточке;
* нет широких разрешений, нет удалённого кода, нет аналитики — формальные пункты закрыты;
* заметка ревьюеру объясняет механику и даёт тестовую ссылку.

Если откажут: Edge Add-ons и Opera принимают те же сборки, а для Chrome остаётся
`release/rutube-tools-chromium.zip` с сайта — установка через «Загрузить распакованное».

## 8. Если проверка не прошла

| Сообщение | Причина | Что делать |
|---|---|---|
| `The "data_collection_permissions" property is missing` | устаревший zip | пересоберите `python3 build.py`; в актуальном манифесте поле есть |
| `manifest.json is not valid` | в архиве вложенная папка | `manifest.json` должен быть в корне zip — `build.py` это гарантирует |
| `uses eval / remote code` | попалась старая сборка | в проекте нет `eval`; напишите ревьюеру, что mux.js собран локально |
| Отказ «facilitating download of copyrighted content» | политика Chrome/Edge | не спорить шаблоном: уточнить, что поддержка DRM и эфиров отсутствует, что данные не собираются, приложить ссылку на политику конфиденциальности. Если отказ повторится — публиковаться на AMO, Opera и с сайта |
| Просят обосновать `downloads` / `storage` | обычная практика | готовый текст в `docs/store/listing-ru.md` |
| Требуют исходники бандла | если в пакете минифицированный чужой код | mux.js лежит с `mux.js.LICENSE`, ссылка на репозиторий есть в карточке |

Ревьюеры отвечают в переписке карточки — отвечайте коротко и по делу, в тот же день.
Один вежливый ответ с техническими деталями ускоряет повторную проверку заметнее, чем правки описания.
