Установленная из AMO версия остаётся после перезапуска и обновляется автоматически.
`update_url` и unlisted-подпись для этого канала не нужны. Временная установка через
`about:debugging` остаётся только способом проверить неподписанную сборку разработчика.

### Обновление через API

Для новой версии нужны одноразовые ключи со страницы
<https://addons.mozilla.org/en-US/developers/addon/api/key/>: **JWT issuer** и **JWT secret**.
Их нельзя коммитить, вставлять в скрипты или оставлять в файлах рабочей папки.

```bash
python3 build.py
AMO_JWT_ISSUER='user:...' AMO_JWT_SECRET='...' \
  python3 tools/amo-publish.py release/rutube-tools-firefox.zip
```

Скрипт загружает zip, ждёт валидацию и добавляет версию к существующему slug
`rutube-tools`. JWT использует `iss` = issuer и уникальный `jti` = nonce; секрет нужен
только для подписи HMAC-SHA256 и в токен не помещается.

После публикации ключи можно отозвать кнопкой **Revoke** на той же странице. Для следующего
обновления выпускают новые. Секреты AMO в GitHub Actions для постоянной автоматизации не нужны.

### Скриншоты и подписи

Все девять изображений уже загружены. Если подпись потребуется восстановить или обновить,
`--previews` работает идемпотентно по позиции и не загружает существующие изображения заново:

```bash
AMO_JWT_ISSUER='user:...' AMO_JWT_SECRET='...' \
  python3 tools/amo-publish.py --previews
```

### Лимиты AMO

| Действие | Симптом | Правило |
|---|---|---|
| Частые PATCH карточки и подписей | `429 Request was throttled` | Собирать связанные поля в один PATCH |
| Загрузка и изменение скриншотов | `429 … Expected available in N seconds` | Не долбить API и не ждать часами в CI; завершить позже или через Developer Hub |

Не проверяйте возможность записи пробными строками: они попадут в публичную карточку и
израсходуют лимит. Читать состояние можно GET-запросами, записывать — только осмысленные данные.

### Ручная загрузка новой версии

1. <https://addons.mozilla.org/developers/> → карточка `rutube-tools` → **New Version**.
2. Загрузить `release/rutube-tools-firefox.zip` в канал **listed**.
3. Проверить заметки версии и заметку ревьюеру из `docs/store/listing-ru.md`.
4. Дождаться валидации и отправить на проверку.
5. После одобрения проверить, что публичная версия сменилась и обновление устанавливается.

Для новой карточки с нуля тексты, категория, лицензия, иконки, промо и порядок скриншотов
лежат в `docs/store/`; для существующей карточки повторно заполнять их не нужно.

## 4. Chrome Web Store

1. <https://chrome.google.com/webstore/devconsole> → войти в аккаунт Google.
2. Оплатить **5 $** (один раз за аккаунт) и включить **двухэтапную аутентификацию** —
   без неё кнопка публикации недоступна.
3. **Add new item** → `release/rutube-tools-chromium.zip`.
4. Вкладки карточки:
   * **Store listing** — название, краткое и полное описание, категория, скриншоты, плитки
     `promo-marquee.png` и `promo-small.png`.
   * **Privacy practices** — политика конфиденциальности по URL, «не собирает данные»
     (ничего не выбираем в категориях данных), обоснование каждого разрешения из
     `docs/store/listing-ru.md`.
   * **Distribution** — публичная, все регионы.
5. **Submit for review**.

### Честно о риске

Правила Chrome Web Store прямо запрещают «содействовать скачиванию контента в нарушение прав
правообладателей» и отдельно упоминают YouTube. Расширение для RuTube под эту формулировку
формально не попадает (это не YouTube), но ревьюер может счесть любой видеограббер
нарушением. Вероятность отказа реальная, и повлиять на неё из кода нельзя.

Что снижает риск:
* в описании — только свои формулировки про «сохранить видео, на которое у вас есть право»,
  без слов «скачать любое видео», «без ограничений», «обойти»;
* DRM и прямые эфиры явно не поддерживаются, и это написано в карточке;
* нет широких разрешений, нет удалённого кода, нет аналитики — формальные пункты закрыты;
* заметка ревьюеру объясняет механику и даёт тестовую ссылку.

Если откажут: Edge Add-ons и Opera принимают те же сборки, а для Chrome остаётся
`release/rutube-tools-chromium.zip` с сайта — установка через «Загрузить распакованное».

## 7. После публикации новой версии

1. Проверить ссылки на карточки магазинов и при необходимости обновить README, лендинг
   и `installUrl` в JSON-LD.
2. Убедиться, что GitHub Release содержит три пакета и `SHA256SUMS`; заметки релиза
   собираются из раздела текущей версии в `docs/CHANGELOG.md`.
3. Проверить успех workflows **Checks**, **Release** и **Pages**. Для новых тегов Release
   также создаёт build-provenance attestations через GitHub OIDC/Sigstore.
4. Обновления: поднять версию в двух манифестах и `docs/CHANGELOG.md`, выполнить
   `python3 build.py` и `python3 tools/check-versions.py`, затем загрузить новый zip в магазины.
   `gecko.id` не меняется.

### Проверка загруженных файлов

Контрольные суммы создаются при каждой локальной сборке:

```bash
python3 build.py
cd release
sha256sum -c SHA256SUMS
```

Для файлов, скачанных из Release, `SHA256SUMS` должен лежать рядом с пакетами. Проверка
provenance для релизов, собранных workflow с attestations:

```bash
gh attestation verify rutube-tools-firefox.zip --repo xxnetme/rutube-tools
gh attestation verify rutube-tools-firefox.xpi  --repo xxnetme/rutube-tools
gh attestation verify rutube-tools-chromium.zip --repo xxnetme/rutube-tools
```

Attestation подтверждает, из какого репозитория и workflow собран файл; это не замена
проверке кода, магазинной подписи или контрольной сумме.

## 8. Если проверка не прошла

| Сообщение | Причина | Что делать |
|---|---|---|
| `The "data_collection_permissions" property is missing` | устаревший zip | пересоберите `python3 build.py`; в актуальном манифесте поле есть |
| `manifest.json is not valid` | в архиве вложенная папка | `manifest.json` должен быть в корне zip — `build.py` это гарантирует |
| `uses eval / remote code` | попалась старая сборка | в проекте нет `eval`; напишите ревьюеру, что mux.js собран локально |
| Отказ «facilitating download of copyrighted content» | политика Chrome/Edge | не спорить шаблоном: уточнить, что поддержка DRM и эфиров отсутствует, что данные не собираются, приложить ссылку на политику конфиденциальности. Если отказ повторится — публиковаться на AMO, Opera и с сайта |
| Просят обосновать `downloads` / `storage` | обычная практика | готовый текст в `docs/store/listing-ru.md` |
| Требуют исходники бандла | если в пакете минифицированный чужой код | mux.js лежит с `mux.js.LICENSE`, ссылка на репозиторий есть в карточке |

Ревьюеры отвечают в переписке карточки — отвечайте коротко и по делу, в тот же день.
Один вежливый ответ с техническими деталями ускоряет повторную проверку заметнее, чем правки описания.
