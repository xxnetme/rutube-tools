# OPFS-прототип: предварительный замер

Дата: 06.11.2026. Статус: **локальный изолированный прототип**, не часть расширения и не
изменение рабочего пути загрузки. Исходный отчёт:
[`tests/opfs/results/2026-11-06-64mib.json`](../tests/opfs/results/2026-11-06-64mib.json).

## Метод

- 64 МиБ детерминированных данных, блоки по 1 МиБ;
- Blob и OPFS запускались в **отдельных свежих процессах** Chromium 158.0.8127.18 и Firefox 159.0;
- OPFS записывается из Dedicated Worker через `createSyncAccessHandle()`;
- после записи данные потоково прочитаны; размер и CRC32 (`ec1b524b`) совпали с Python во всех четырёх режимах;
- RSS — сумма `VmRSS` дерева WebDriver и браузерных процессов, сэмплы каждые 100 мс;
- каждый режим выполнен один раз. Это предварительный сигнал, не статистически надёжный бенчмарк.

Среда: Linux x86_64, Intel Xeon 2,60 ГГц, 2 логических CPU. Воспроизведение: `npm run bench:opfs`.

## Результат

| Браузер | Путь | Полный цикл | Чтение + CRC32 | Пик ΔRSS | Usage после очистки |
|---|---:|---:|---:|---:|---:|
| Chromium | Blob | 381,9 мс | 274,0 мс | 117,2 МиБ | 0 |
| Chromium | OPFS | 343,8 мс | 235,2 мс | 97,2 МиБ | 0 |
| Firefox | Blob | 781,0 мс | 667,0 мс | 150,4 МиБ | 0 |
| Firefox | OPFS | 1028,0 мс | 901,0 мс | 110,0 МиБ | 491 520 байт = baseline |

Пик ΔRSS у OPFS оказался ниже на 20,0 МиБ в Chromium и на 40,4 МиБ в Firefox **в этом
конкретном запуске**. Это не эквивалент точной экономии памяти файла и не разрешает
сравнивать абсолютный RSS между браузерами.

Скорость неоднородна: в Chromium полный цикл OPFS был примерно на 10 % короче, в Firefox —
примерно на 32 % длиннее, прежде всего из-за фазы чтения. Поэтому формулировка «OPFS всегда
быстрее и экономнее» данными не подтверждается.

## Квота и очистка

- OPFS-файл после цикла отсутствует в обоих браузерах; это проверено отдельно через 500 мс.
- В Chromium usage возвращается к нулю.
- В Firefox сама инициализация OPFS занимает 491 520 байт. До записи usage уже равен этому
  значению, после удаления возвращается ровно к нему; роста после цикла относительно baseline нет.
- Сообщённая квота Firefox в этой временной профильной среде — 103 957 299 байт (около 99 МиБ).
  Замер 2 ГиБ здесь без изменения среды невозможен и **не выполнялся**.

## Решение

OPFS **не включается по умолчанию** и не заменяет текущий путь. Прототип подтвердил базовую
работоспособность Worker + OPFS и дал причину продолжить исследование памяти, но не снял главные
риски: реальный HLS, большие файлы, повторные прогоны, восстановление индекса и выдача результата
через `downloads.download()` без повторной сборки всего файла в RAM.

Полный этап 1.12 должен повторить замеры на больших файлах в среде с достаточной квотой,
проверить экспорт и восстановление после перезапуска. До этого старый путь остаётся основным.
